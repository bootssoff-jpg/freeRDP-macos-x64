# RDP Mac

Нативный клиент RDP для **macOS Intel (x86_64)** на базе **FreeRDP 3.32.2**.
Собственный интерфейс на Swift/AppKit, без X11, SDL и Microsoft Remote Desktop.
Основной сценарий — стабильная работа с текстовым буфером обмена в обе стороны.

> **Статус проверки.** Автоматические тесты (протокол CLIPRDR, кодирование текста,
> жизненный цикл подключения, компоновка `.app`, загрузка встроенных библиотек)
> проходят на macOS 15.8.1 Intel. Реальный сеанс с Windows Server / Windows 10/11
> в этой среде недоступен, поэтому ручной чек-лист из раздела
> [«Проверка с реальным Windows»](#проверка-с-реальным-windows) нужно выполнить
> на вашем сервере. Ниже явно указано, что именно не проверено.

---

## Возможности

- Подключение по RDP с **NLA (по умолчанию)**, **TLS-only** или явно выбранным
  устаревшим **RDP Security**.
- Проверка сертификата **всегда включена**: неизвестный сертификат требует явного
  решения пользователя («Отклонить» по умолчанию, «Принять один раз»,
  «Принять и запомнить»). Автопринятие отключено.
- Отрисовка удалённого рабочего стола в окне AppKit: Retina, масштабирование,
  полноэкранный режим, изменение разрешения через DisplayControl.
- Мышь (включая правую/среднюю/боковые кнопки и колесо) и клавиатура.
- Русский/английский ввод, Unicode, Emoji, многострочный текст.
- **Двусторонний текстовый буфер обмена**: `CF_UNICODETEXT` (UTF-16LE) как
  основной формат, `CF_TEXT` как совместимый fallback.
- Подавление эхо-циклов буфера обмена, тайм-аут запросов, повторная
  синхронизация, диагностика без раскрытия содержимого.
- Профили подключения в JSON **без паролей**; пароль — только в Keychain и
  только по явной галочке.
- Журнал подключения без паролей и содержимого буфера, экспорт журнала.
- `Ctrl+Alt+Delete` отправляется как `Ctrl+Alt+End` (штатная замена RDP) из
  меню/панели, чтобы не перехватывать системное сочетание macOS.

## Ограничения

- Только **текст**. Изображения, файлы, перенаправление папок/принтеров,
  звук, камера, смарт-карты и IME не поддерживаются.
- Нет RD Gateway, RemoteApp/RAIL, мультимонитора и автоматического
  переподключения (есть кнопка «Переподключиться»).
- Kerberos не собран; NLA работает через NTLM/SSPI WinPR.
- Политика сервера может запрещать буфер обмена или CLIPRDR; клиент это не обходит.
- Приложение не прошло нотаризацию Apple. Локальная сборка подписана ad-hoc;
  для распространения нужен Developer ID и notarization (см. ниже).
- Сборка и бинарник — **только x86_64**. На Apple Silicon приложение может
  запускаться через Rosetta 2, но нативная arm64-сборка не подготовлена.

## Требования к сборке

- macOS 12+ на Intel.
- Command Line Tools (полный Xcode не обязателен), Swift 6.x.
- CMake 3.21+.
- Homebrew и `openssl@3` (`brew install cmake openssl@3`).
- Git и сеть для однократной загрузки FreeRDP 3.32.2.

Проверено на: macOS 15.8.1, Swift 6.1.2, CMake 4.4.3, OpenSSL 3.6.4
(Homebrew), FreeRDP tag `3.32.2`, commit `97eff6ddfbbfaa8e42a126d362686bd001ff8bdc`.

## Сборка

```bash
brew install cmake openssl@3
make app          # скачает/соберёт FreeRDP и создаст build/RDP Mac.app
make test         # автоматические тесты
open "build/RDP Mac.app"
```

Или по шагам:

```bash
./scripts/build_freerdp.sh   # статические библиотеки FreeRDP -> vendor/freerdp-install
./scripts/build_app.sh       # Swift/ObjC + бандл + OpenSSL внутри .app
./scripts/run_tests.sh       # unit/protocol/lifecycle тесты
```

Результаты:

- `build/RDP Mac.app` — самодостаточное приложение (OpenSSL внутри
  `Contents/Frameworks`, `@rpath`, ad-hoc подпись);
- `build/dist/RDP-Mac-1.0.0-x86_64-unsigned.zip` — архив для передачи.

Проверить, что приложение не зависит от Homebrew:

```bash
otool -L "build/RDP Mac.app/Contents/MacOS/RDPMac"
# должно быть @rpath/libssl.3.dylib и @rpath/libcrypto.3.dylib, без /usr/local
"build/RDP Mac.app/Contents/MacOS/RDPMac" --selftest
```

`--selftest` проверяет версию FreeRDP, создание/освобождение контекста,
round-trip Unicode и CF_TEXT, не подключаясь к серверу.

## Использование

1. Запустите `RDP Mac.app`.
2. Укажите сервер, порт (по умолчанию 3389), пользователя и домен.
3. Выберите безопасность: **NLA/TLS** (рекомендуется), **TLS-only** или
   **RDP Security** только для старых серверов.
4. При первом подключении проверьте отпечаток SHA-256 сертификата и примите его
   явно. «Принять и запомнить» сохраняет сертификат в `known_hosts` FreeRDP.
5. После подключения откройте «Буфер обмена…» на панели сеанса или меню
   «Буфер обмена» для диагностики и ручной синхронизации.

Горячие клавиши:

| Действие | Сочетание |
|---|---|
| Параметры подключения | `⌘,` |
| Отключиться | `⌘D` |
| Ctrl+Alt+Delete | `⌘⇧Delete` |
| Полный экран | `⌘⌃F` |
| Отправить Mac → Windows | `⌘⇧C` |
| Запросить Windows → Mac | `⌘⇧V` |
| Полная ресинхронизация буфера | `⌘⌥⇧V` |
| Диагностика буфера | `⌘⇧B` |
| Журнал | `⌘⇧L` |
| Экспорт журнала | `⌘⇧E` |

`Command` по умолчанию передаётся как `Ctrl` (галочка в форме), поэтому
`⌘C`/`⌘V` работают как `Ctrl+C`/`Ctrl+V` внутри сеанса. Меню macOS имеет
приоритет для своих сочетаний.

## Буфер обмена: как устроен

- Локальная сторона: `NSPasteboardTypeString` → `CF_UNICODETEXT`
  (UTF-16LE + NUL). Для `CF_TEXT` — Windows-1251/CP1252 или UTF-8 для
  нестандартных источников.
- Удалённая сторона: CLIPRDR `Format List`, `Format Data Request/Response`,
  `Monitor Ready`, capabilities только с текстовыми форматами.
- При появлении текста в Windows клиент запрашивает данные и записывает их в
  macOS pasteboard.
- При изменении macOS pasteboard (опрос 0.4 с) клиент объявляет
  `CF_UNICODETEXT`; Windows запрашивает данные, клиент отвечает.
- Эхо-подавление: запомненный `changeCount` после собственной записи и
  сравнение последнего текста не дают бесконечному циклу.
- Лимит 32 МиБ; запросы без ответа истекают через 5 с; ошибки видны в
  диагностике и журнале.
- **Содержимое буфера не пишется ни в журнал, ни в диагностику** — только
  форматы, количество, время и коды ошибок.
- Синхронизация работает, пока сеанс активен, в том числе когда окно RDP не в
  фокусе. Если это нежелательно, снимите галочку «Двусторонний текстовый буфер
  обмена» в профиле.

Для поддержки можно открыть реальные окна диагностики/журнала при запуске:

```bash
"build/RDP Mac.app/Contents/MacOS/RDPMac" --diagnostics
"build/RDP Mac.app/Contents/MacOS/RDPMac" --log
```

## Безопасность и приватность

- Автопринятие сертификатов отключено; по умолчанию в диалоге выбран отказ.
- Пароль не попадает в JSON-профили и журнал. Keychain используется только при
  включённой галочке; «Забыть пароль» удаляет запись.
- Пароль неизбежно находится в памяти процесса на время сеанса.
- Журнал: `~/Library/Logs/RDPMac/rdp.log` (ротация 2 МиБ).
- Профили: `~/Library/Application Support/RDPMac/profiles.json`.
- Приложение не имеет App Sandbox (нужны сеть, pasteboard, Keychain и
  произвольный выбор файла для экспорта). Это допустимо для локальной сборки;
  для Mac App Store потребовалась бы отдельная sandbox-конфигурация.
- Ad-hoc подпись не является доверенной для Gatekeeper. Для распространения
  подпишите Developer ID и нотаризуйте:

```bash
codesign --force --deep --options runtime --sign "Developer ID Application: ..." \
    "build/RDP Mac.app"
xcrun notarytool submit build/dist/RDP-Mac-1.0.0-x86_64-unsigned.zip \
    --keychain-profile "notary-profile" --wait
xcrun stapler staple "build/RDP Mac.app"
```

## Архитектура

```
Sources/
  Bridge/
    RDPMacBridge.h            публичный ObjC API для Swift
    RDPMacClient.m            FreeRDP instance, сертификаты, ввод, кадры, потоки
    RDPMacClipboard.m         контроллер CLIPRDR, эхо-подавление, диагностика
    RDPMacClipboardText.m     CF_UNICODETEXT / CF_TEXT кодирование
    RDPMacInternal.h          приватные типы и интерфейсы
    RDPMacModels.m            DTO для Swift
  App/
    main.swift                точка входа, --selftest
    AppDelegate.swift         меню, жизненный цикл приложения
    MainWindowController.swift форма/сеанс, делегат клиента, resize, сертификаты
    ConnectFormView.swift      форма подключения и профили
    SessionView.swift          панель сеанса и overlay состояния
    RDPView.swift              отрисовка BGRX, мышь, клавиатура
    DiagnosticsWindowController.swift
    LogWindowController.swift
    Profiles.swift             профили, Keychain, режимы
    LogStore.swift             журнал и экспорт
    UIControls.swift           небольшие AppKit-хелперы
Resources/Info.plist
Tests/                        ObjC тесты без реального RDP-сервера
scripts/                      воспроизводимая сборка и тесты
vendor/                       FreeRDP (не коммитится, скачивается скриптом)
```

Потоковая модель:

- FreeRDP-сеанс живёт в отдельном `NSThread`; UI и delegate-вызовы — на main.
- Кадровый буфер защищён мьютексом; `RDPView` копирует кадр и рисует BGRX→CGImage.
- Ввод синхронизирует модификаторы и отправляет scancode/Unicode-события.
- CLIPRDR-контроллер работает на main через таймеры и колбэки канала.

## Тесты

```bash
make test
```

Что покрыто автоматически:

- `Tests/clipboard_tests.m` — UTF-16LE/CF_TEXT round-trip, кириллица, Emoji,
  1+ МиБ текста, NUL/odd-length, CP1251, UTF-8 fallback, отказ форматов.
- `Tests/clipboard_protocol_tests.m` — реальный `NSPasteboard` + фальшивый
  CLIPRDR-интерфейс: capabilities, Format List, запрос/ответ данных,
  отсутствие эха, ошибки, отсутствие содержимого в отчёте.
- `Tests/bridge_lifecycle.m` — валидация аргументов, реальный TCP-отказ
  (`127.0.0.1:1`), состояние `Failed`, повторный запуск на том же объекте,
  освобождение клиента, запуск нового клиента.
- `--selftest` внутри `.app` — загрузка встроенных OpenSSL/FreeRDP.

Эти тесты **не заменяют** проверку с настоящим Windows: они не проверяют
NLA-аутентификацию, реальный CLIPRDR-обмен с mstsc/rdpdr и политику сервера.

## Проверка с реальным Windows

Ручной чек-лист (выполнить на вашем сервере):

- [ ] Подключение с NLA и корректным паролем/доменом.
- [ ] Неверный пароль → понятная ошибка, приложение не падает.
- [ ] Первое подключение → диалог сертификата; «Отклонить» действительно
      прерывает подключение; «Принять один раз» не создаёт запись;
      «Принять и запомнить» позволяет повторное подключение без вопроса.
- [ ] Рабочий стол отображается, мышь и колесо работают в обе стороны.
- [ ] Русский и английский ввод, Shift/Ctrl/Alt, CapsLock, Emoji.
- [ ] `⌘C`/`⌘V` внутри сеанса работают как `Ctrl+C`/`Ctrl+V`.
- [ ] Текст из Windows → Mac: Блокнот → выделить → `Ctrl+C` → вставить в
      TextEdit на Mac.
- [ ] Текст из Mac → Windows: скопировать в TextEdit → вставить в Блокнот.
- [ ] Многострочный текст и кириллица в обе стороны.
- [ ] Повторное копирование того же текста не вызывает циклов (счётчики в
      диагностике растут умеренно, CPU не растёт).
- [ ] «Отправить Mac → Windows» и «Запросить Windows → Mac» вручную.
- [ ] «Полная ресинхронизация» после смены фокуса окон.
- [ ] Изменение размера окна → разрешение меняется (если сервер поддерживает
      DisplayControl); иначе остаётся исходным.
- [ ] Полный экран и выход из него.
- [ ] `Ctrl+Alt+Delete` из меню/панели открывает экран безопасности Windows.
- [ ] Отключение, повторное подключение, закрытие приложения без зависаний.
- [ ] Экспорт журнала; убедиться, что в нём нет пароля и текста буфера.

Если какой-то пункт не работает, приложите диагностику буфера и журнал:
«Буфер обмена…» → «Копировать отчёт», «Диагностика» → «Экспорт журнала…».

## Известные особенности

- Если сервер не поддерживает DisplayControl, размер кадра остаётся таким,
  каким его отдаёт сервер; окно масштабирует его с сохранением пропорций.
- Направление колеса зависит от «Natural Scrolling»; при необходимости
  сопоставление легко поменять в `RDPView.scrollWheel`.
- `Command`-сочетания, занятые меню macOS, не уходят в Windows.
- При смене профиля поле пароля очищается, если для профиля нет записи в
  Keychain.
- При подключении без галочки «Сохранить пароль» старая запись Keychain для
  этого сервера/пользователя удаляется.

## Если сборка не проходит

- **`OpenSSL 3 not found`** — `brew install openssl@3`;
  проверьте `brew --prefix openssl@3`.
- **Ошибка `OPENSSL_sk_set_cmp_thunks` при линковке** — FreeRDP собрался с
  заголовками OpenSSL 4 из `/usr/local/include`. Скрипт уже добавляет
  `-I<openssl@3>/include` и проверяет это; при ручной сборке сделайте так же
  и пересоберите FreeRDP с `--force`.
- **`FreeRDP is not built`** — выполните `./scripts/build_freerdp.sh`.
- **Приложение не запускается после переноса** — проверьте
  `codesign --verify --deep --strict` и `otool -L`; папка `Contents/Frameworks`
  должна ехать вместе с `.app`.
- **Gatekeeper блокирует** — для локальной сборки:
  `xattr -dr com.apple.quarantine "build/RDP Mac.app"` (только для своего
  неподписанного бинарника; для распространения используйте notarization).

## CI

`.github/workflows/build.yml` собирает проект на GitHub-hosted раннере
`macos-15-intel` (Intel x86_64; метка проверена по документации GitHub,
см. ссылку в комментарии workflow). CI выполняет сборку FreeRDP, тесты,
упаковку, проверку `@rpath`/подписи и загружает unsigned-артефакт.
Секреты подписи не используются.
