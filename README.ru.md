# RDP Mac

[![CI](https://github.com/bootssoff-jpg/freeRDP-macos-x64/actions/workflows/build.yml/badge.svg?branch=main)](https://github.com/bootssoff-jpg/freeRDP-macos-x64/actions/workflows/build.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Latest release](https://img.shields.io/github/v/release/bootssoff-jpg/freeRDP-macos-x64?display_name=tag&sort=semver)](https://github.com/bootssoff-jpg/freeRDP-macos-x64/releases)

Нативный клиент RDP для **macOS Intel (x86_64)** на базе **FreeRDP 3.32.2**.
Интерфейс написан на Swift/AppKit; код и runtime Microsoft Remote Desktop не
используются. Основной сценарий — надёжный **двусторонний текстовый буфер
обмена**.

[English](README.md) · **Русский**

![Менеджер подключений RDP Mac с демонстрационными профилями](docs/images/connections.png)

*Реальное окно приложения с демонстрационными профилями на зарезервированных
доменах `.invalid`. Удалённый сеанс не имитируется.*

## Статус проверки

Автоматические тесты (протокол CLIPRDR, кодирование текста, жизненный цикл
подключения, несколько окон, компоновка `.app`, загрузка встроенных библиотек)
проходят на macOS 15.8.1 Intel. Реальный сеанс с Windows Server / Windows 10/11
в этой среде недоступен, поэтому ручной чек-лист из
[docs/testing.md](docs/testing.md) нужно выполнить на вашем сервере. Пункты,
помеченные как ручные, не считаются проверенными.

## Возможности

- Несколько независимых RDP-сессий в отдельных окнах. `⌘N` — новое окно
  подключения, `⌘0` — общий менеджер подключений.
- Менеджер подключений: группы профилей, поиск по имени/серверу/пользователю/
  группе, множественный выбор и число сессий для профиля.
- Профили в JSON **без паролей**. Пароль хранится только в Keychain и только
  после явной галочки. Если пароля нет, форма попросит его ввести.
- NLA/TLS по умолчанию, TLS-only или устаревший RDP Security для старых
  серверов.
- Проверка сертификата включена всегда. Неизвестный сертификат требует явного
  решения: отклонить (по умолчанию), принять один раз или принять и запомнить.
  Автопринятие невозможно.
- Режим совместимости TLS (`SECLEVEL=0`) для старых Windows-серверов с
  SHA-1/RSA-1024. Включается только действием пользователя, не отключает
  проверку сертификата и никогда не включён по умолчанию.
- Отрисовка кадра в AppKit: Retina, масштабирование, полный экран,
  DisplayControl, мышь (включая правую/среднюю/боковые кнопки и колесо) и
  клавиатура.
- Русский/английский ввод, Unicode, Emoji, многострочный текст.
- Двусторонний текстовый буфер: `CF_UNICODETEXT` (UTF-16LE) как основной
  формат, `CF_TEXT` как best-effort fallback.
- Подавление эха, тайм-аут запросов, ручная ресинхронизация и диагностика,
  которая показывает только форматы, счётчики, время и коды ошибок — без
  содержимого.
- Только передняя сессия может обращаться к общему pasteboard macOS. Фоновые
  сессии и запоздалые ответы изолированы.
- Журнал без паролей и содержимого буфера; экспорт из сессии или менеджера
  подключений. `Ctrl+Alt+Delete` отправляется как `Ctrl+Alt+End` — штатная
  замена в RDP.

## Ограничения

- **Только текст.** Изображения, файлы, перенаправление папок/принтеров, звук,
  камера, смарт-карты и IME не поддерживаются.
- Нет RD Gateway, RemoteApp/RAIL, мультимонитора и автоматического
  переподключения (есть кнопка «Переподключиться»). Kerberos не собран; NLA
  работает через NTLM/SSPI WinPR.
- Политика сервера может запрещать буфер обмена или CLIPRDR; клиент это не
  обходит.
- Приложение **не нотаризовано**. Локальная сборка подписана ad-hoc; для
  распространения нужны Developer ID и notarization. См.
  [docs/releasing.md](docs/releasing.md).
- Бинарник **только x86_64**. На Apple Silicon возможен запуск через Rosetta 2;
  нативной arm64-сборки нет.

## Требования

- **macOS 12+ на Intel x86_64** для запуска.
- Для сборки: Command Line Tools (полный Xcode не обязателен), Swift 6.x,
  CMake 3.21+, Git и сеть.
- OpenSSL 3 собирается проектом из закреплённого исходника; Homebrew OpenSSL не
  требуется и не берётся из bottle. Homebrew `cmake` — по желанию.

Сборка проверена на macOS 15.8.1, Swift 6.1.2, CMake 4.4.3, OpenSSL 3.6.4.
Deployment target — macOS 12.0; скрипт сборки отвергает встроенную библиотеку,
которая требует более новую macOS.

## Сборка

```bash
make app          # OpenSSL + FreeRDP + build/RDP Mac.app
make test         # автоматические тесты без RDP-сервера
open "build/RDP Mac.app"
```

По шагам:

```bash
./scripts/build_openssl.sh    # OpenSSL 3.6.4 -> vendor/openssl-install
./scripts/build_freerdp.sh    # статический FreeRDP -> vendor/freerdp-install
./scripts/build_app.sh        # Swift/ObjC + OpenSSL внутри .app
./scripts/run_tests.sh        # unit/protocol/lifecycle тесты
```

`libssl.3.dylib` и `libcrypto.3.dylib` лежат в `Contents/Frameworks` и
подключены через `@rpath`; Homebrew в runtime не нужен. Сборка проверяет
архитектуру, relocate-пути, подпись и минимальную версию macOS.

```bash
otool -L "build/RDP Mac.app/Contents/MacOS/RDPMac"
# должно быть @rpath/libssl.3.dylib и @rpath/libcrypto.3.dylib, без /usr/local
"build/RDP Mac.app/Contents/MacOS/RDPMac" --selftest
```

## Артефакты релиза

```bash
make dist
```

`make dist` подписывает bundle (Developer ID, если задан), проверяет его и
только **после подписи** создаёт ZIP, DMG и `SHA256SUMS`:

```text
build/dist/RDP-Mac-1.0.0-x86_64-unsigned.zip
build/dist/RDP-Mac-1.0.0-x86_64-unsigned.dmg
build/dist/SHA256SUMS
```

Без credentials артефакты явно помечены `unsigned`; Gatekeeper попросит
подтверждение. Для подписи и нотаризации:

```bash
DEVELOPER_ID_APPLICATION="Developer ID Application: …" \
NOTARY_PROFILE="notary-profile" \
make dist
```

Скрипты ничего не публикуют и не меняют видимость репозитория. Подробности:
[docs/releasing.md](docs/releasing.md), подготовленные
[release notes](docs/release-notes-1.0.0.ru.md).

## Использование

Приложение открывает **менеджер подключений**, а не пустое окно сессии.
Создайте профиль кнопкой «Новое подключение», заполните сервер и сохраните.
Необязательное поле «Группа» разделяет рабочие и домашние серверы; старые
профили попадают в «Без группы».

Двойной щелчок открывает профиль в новом окне. Можно выделить несколько
профилей с Command/Shift и нажать «Открыть выбранные». Если профиль разрешает
сохранение пароля и Keychain уже содержит его, подключение начнётся сразу;
иначе форму нужно заполнить. Один профиль можно открыть повторно — число
одновременных входов с одной учётной записью определяет Windows-сервер.

![Форма подключения с демонстрационными данными](docs/images/connection-form.png)

*Реальная форма подключения с демо-данными. Пароль не подставляется из JSON.*

Общий pasteboard macOS синхронизируется **только с активной сессией, пока
приложение на переднем плане**. Фоновые сессии не читают и не перезаписывают
его. При переходе в менеджер подключений или другое приложение обмен
приостанавливается. Запоздалый ответ фоновой сессии отбрасывается, даже если
вернуться в неё.

Закрытие одного окна отключает только его сеанс. `⌘Q` отключает все сессии и
ждёт до трёх секунд на каждую.

### Горячие клавиши

| Действие | Сочетание |
|---|---|
| Новая сессия | `⌘N` |
| Менеджер подключений | `⌘0` |
| Параметры подключения | `⌘,` |
| Отключиться | `⌘D` |
| Ctrl+Alt+Delete | `⌘⇧Delete` |
| Полный экран | `⌘⌃F` |
| Отправить Mac → Windows | `⌘⇧C` |
| Запросить Windows → Mac | `⌘⇧V` |
| Полная ресинхронизация | `⌘⌥⇧V` |
| Диагностика буфера | `⌘⇧B` |
| Журнал | `⌘⇧L` |
| Экспорт журнала | `⌘⇧E` |

`Command` по умолчанию передаётся как `Ctrl` (галочка в форме), поэтому
`⌘C`/`⌘V` работают как `Ctrl+C`/`Ctrl+V` внутри сеанса. Сочетания, занятые
меню macOS, имеют приоритет.


## Как устроен буфер обмена

- Локально: `NSPasteboardTypeString` → `CF_UNICODETEXT` (UTF-16LE + NUL).
  `CF_TEXT` — Windows-1251/CP1252 или UTF-8 для нестандартных источников.
- Удалённо: CLIPRDR `Monitor Ready`, capabilities только с текстовыми
  форматами, `Format List`, `Format Data Request/Response`.
- Изменение pasteboard macOS определяется опросом раз в 0.4 с; список форматов
  Windows вызывает запрос данных.
- Подавление эха сравнивает последний текст и не позволяет собственному
  изменению pasteboard запустить бесконечный цикл.
- Лимит 32 МиБ, тайм-аут запроса 5 с. Счётчики и ошибки видны в диагностике;
  содержимое не пишется в журнал.
- Запросы данных последовательны: новый формат ждёт ответа на предыдущий.
  После тайм-аута запоздалый ответ отбрасывается. Если сервер перестал
  отвечать совсем, сессию нужно переподключить.
- Синхронизируется только активная сессия; фоновые приостановлены.

Подробнее: [docs/architecture.md](docs/architecture.md).

## Безопасность и приватность

- Автопринятие сертификатов отключено; по умолчанию выбран отказ.
- Обычный TLS использует OpenSSL security level 1. Режим совместимости
  (`SECLEVEL=0`) запускается только после явного подтверждения и не отключает
  проверку/подтверждение сертификата.
- Пароли не попадают в JSON-профили и журнал. Keychain используется только
  после явного согласия; «Забыть пароль» удаляет запись.
- Пароль неизбежно находится в памяти процесса на время сеанса.
- Журнал: `~/Library/Logs/RDPMac/rdp.log` (ротация 2 МиБ).
- Профили: `~/Library/Application Support/RDPMac/profiles.json`.
- App Sandbox не используется: нужны сеть, pasteboard, Keychain и произвольный
  выбор файла для экспорта. Для Mac App Store потребовалась бы отдельная
  sandbox-конфигурация.
- Ad-hoc подпись не доверена Gatekeeper. Developer ID и notarization описаны в
  [docs/releasing.md](docs/releasing.md).

## Архитектура

Кратко: каждый FreeRDP-сеанс живёт в отдельном `NSThread`; UI и delegate
вызовы приходят на main. Кадр защищён мьютексом, `RDPView` копирует его в
буфер с проверкой capacity и рисует BGRX как `CGImage`. Ввод синхронизирует
модификаторы и отправляет scancode/Unicode. CLIPRDR-колбэки выполняются на
main; контроллер использует таймеры. Полная схема — в
[docs/architecture.md](docs/architecture.md).

## Тесты

```bash
make test
```

- `Tests/clipboard_tests.m` — UTF-16LE/CF_TEXT round-trip, кириллица, Emoji,
  текст >1 МиБ, NUL/нечётная длина, CP1251, UTF-8 fallback, отказ форматов.
- `Tests/clipboard_protocol_tests.m` — реальный `NSPasteboard` и фальшивый
  CLIPRDR: capabilities, формат-лист, запрос/ответ, отсутствие эха, ошибки,
  отсутствие содержимого в отчёте, изоляция фоновой сессии, запоздалые
  ответы, последовательные запросы.
- `Tests/bridge_lifecycle.m` — валидация аргументов, реальный TCP-отказ
  (`127.0.0.1:1`), состояние `Failed`, повторный запуск на том же объекте,
  освобождение и новый клиент; проверка capacity кадра при росте высоты.
- `Tests/session_windows.swift` — независимые окна, маршрутизация меню,
  закрытие одного окна, завершение всех контроллеров, группы/поиск и чтение
  старых профилей без поля группы.
- `--selftest` внутри `.app` — загрузка встроенных OpenSSL/FreeRDP.

Автотесты **не заменяют** реальный Windows: NLA, настоящий обмен CLIPRDR и
политика сервера проверяются вручную по [docs/testing.md](docs/testing.md).
